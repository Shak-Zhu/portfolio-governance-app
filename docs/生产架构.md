# 生产架构｜v1.0

```text
Browser Web App
  └─ Cloudflare Worker (静态前端 + REST API + 后续 /mcp)
       ├─ D1: `pmo-governance-prod`（binding: `DB`）
       └─ R2: `pmo-governance-backups-prod`（binding: `BACKUPS`）
```

## 核心规则

- `steps` 是每根甘特条的唯一数据来源；每条包含名称、开始、结束和状态。
- `projects.parent_id` 表示父子层级。
- 项目关联资料采用一对多数据模型，保存显示标题与 `http(s)` URL；资料与项目同生命周期管理。
- Stage 支持新增与编辑；已被项目使用的 Stage 不可删除。
- 仅顶级项目可以归档；归档前必须验证所有后代项目均已完成。
- 所有网页与 MCP 写操作写入 `audit_events`，记录 actor、时间、对象、变更前后摘要。

## 数据安全边界

- D1 为主数据源；Worker 重部署不得删除或重建已有业务数据。
- schema 变更只能用可重复执行的 migration。
- R2 Bucket 已开通并创建；每日逻辑备份、保留策略与恢复演练仍须在 WP-002B 实现与验证，当前不得模拟“已备份”。
- MCP 写操作不得匿名开放；认证方案在 WP-003 确定并实现。
